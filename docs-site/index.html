1. Problem Statement & Core Objectives

Traditional cloud storage solutions expose unencrypted data and monolithic files to provider infrastructure.

Vulnerability #1

Data Leakage at Rest

Storing unencrypted raw files allows rogue insiders or misconfigured bucket permissions to expose sensitive documents directly.

Vulnerability #2

Monolithic Upload Failures

Uploading large 50+ MB files over unstable networks forces users to restart the entire file from 0% upon any transient packet loss.

ShardSafe Solution #1

Zero-Knowledge WebCrypto

Plaintext and passphrases never leave the browser. Every block is encrypted with AES-256-GCM before transmission to S3.

ShardSafe Solution #2

Independent 1 MiB Blocks

Files are divided into numbered segments. Failed chunks retry independently, eliminating server bottlenecks via presigned S3 URLs.

2. Mandatory AWS Services Breakdown

Every service performs genuine production cloud workloads with least-privilege security configurations.

Compute Layer

Amazon EC2

Hosts Node.js and Express backend API. Issues short-lived presigned S3 URLs, coordinates upload verification, validates user file ownership, and connects to RDS through private VPC networking.

Relational DB

Amazon RDS (PostgreSQL)

Stores users, password hashes (bcrypt), per-file salt, key derivation parameters, block numbers, S3 object keys, unique IVs, checksums, and audit logs. Private security group scoped to EC2.

Object Storage

Amazon S3 Vault

Stores encrypted ciphertext blocks using opaque keys: vault/{userId}/{fileId}/part-XXXXXX.bin. Public access is permanently blocked. Direct transfers via presigned PUT and GET URLs.

CDN Distribution

Amazon CloudFront

Global edge distribution for technical documentation. Serves content via HTTPS with Origin Access Control (OAC), ensuring the documentation S3 bucket remains completely private.

3. File Segmentation & Web Crypto Pipeline

Step-by-step cryptographic sequence executed within the browser's SubtleCrypto sandbox.

STAGE 01
File Slicing
Browser slices binary file into configurable 1 MiB chunks. Reads array buffers in memory without uploading.
STAGE 02
PBKDF2 Key Derivation
Generates 16-byte random salt. Derives 256-bit AES-GCM key from user passphrase using 100,000 iterations of PBKDF2-HMAC-SHA-256.
STAGE 03
AES-256-GCM Encryption
Generates unique 96-bit IV per chunk. Encrypts block with 128-bit authentication tag. Computes SHA-256 checksum of ciphertext.
STAGE 04
Direct S3 Presigned Transfer
Requests signed PUT URL from EC2 API. Streams ciphertext directly to private S3 bucket. Registers IV and checksum in RDS.
